# 🎯 Vision — 从提示音到任务指挥台

> Attention Plugins 的产品展望。  
> 现在，我们让你"听得到"；未来，我们让你"一处搞定"。

---

## 现状：以提示为主（Phase A · 已完成）

当前版本的 Attention 插件解决的是**"听得到"**的问题：

- 🔊 四类事件提示音（完成 / 失败 / 提问 / 权限）
- 🔔 浏览器系统通知
- ⭐ 主线/支线任务分级提醒（主线完成即响，支线全部完成才响）

它是一个**被动响应**系统：事件发生 → 提醒你 → 你自己去处理。

---

## 展望一：统一出口 — 审批中心（Approval Inbox）

### 核心设想

现在你有多个会话、多个工作区在并行工作。每个 agent 干完活、遇到问题、需要授权时，都**各自为政**地等待你：你必须记住去哪个会话、哪个工作区处理它。

**未来的样子：所有对话统一成一个入口和一个出口。**

> 有人向你汇报，有人在你的不同工作区里干活；干完之后，他们向你汇报——而所有的汇报，都汇入同一个地方。

这就是**审批中心**（Approval Inbox）：

```
┌─────────────────────────────────────────────┐
│  📥 审批中心                    3 件待处理     │
├─────────────────────────────────────────────┤
│  🔒 需要授权                                  │
│  ├─ workspace-A / 重构任务   请求执行 rm -rf  │  [批准] [拒绝] [跳转]
│  └─ workspace-C / 部署任务   请求 git push    │  [批准] [拒绝] [跳转]
│                                             │
│  ❓ 需要回答                                  │
│  └─ workspace-B / 调研任务   "选方案 A 还是 B？"│  [回答] [跳转]
│                                             │
│  ✅ 刚刚完成                                  │
│  └─ workspace-A / 重构任务   "重构完成，47 文件"│  [查看] [归档]
└─────────────────────────────────────────────┘
```

### 关键特征

1. **一处汇报**：跨工作区、跨会话的所有"需要你"事件，汇聚成一个收件箱
2. **就地处理**：批准 / 拒绝 / 回答直接在收件箱完成，agent 不用等你想起它
3. **分级排序**：主线任务的事件置顶；紧急的（权限请求）排在前面
4. **与提示音联动**：Attention 的通知只是审批中心的"门铃"——门铃响了，进来就能办事

### 可行路径（技术视角）

- 事件源已经存在：`pendingInteractions` 快照（question / approval）+ 会话完成事件，本插件已在消费
- 审批动作有现成 API：`session-controller` 提供交互应答能力（批准授权、回答问题）
- 第一步可以做成**只读收件箱**（聚合展示 + 跳转），第二步接入**就地操作**
- 载体：侧边栏 slot 或独立路由页（bundle 插件可注册路由）

## 展望二：统一入口 — 任务看板的进化（Mission Board）

### 现状的问题

DSH 目前的任务看板（任务列表 / 会话总览）功能上是有的，但：

- **不够美观**：信息密度和视觉层级有提升空间
- **不够聚焦**：看不出哪个是主线、哪些是支线、哪些在等你

### 优化方向

| 维度 | 现在 | 未来 |
|------|------|------|
| 视觉 | 平铺列表 | 主线 ⭐ 置顶、支线分组、运行状态动效 |
| 信息 | 基础状态 | 运行时长、最近事件、待处理角标 |
| 操作 | 逐个点开 | 批量归档、一键跳转、筛选（运行中/等待你/已完成） |
| 联动 | 无 | 与审批中心打通：看板上直接看到"3 件待处理" |

**任务看板是入口，审批中心是出口；入口看全局，出口办事情。**

## 阶段路线图

```
Phase A · 提示中心          ← 你在这里
   声音 + 通知 + 主线/支线 ✅
        │
Phase B · 汇总收件箱
   只读聚合所有"需要你"的事件，一个列表看全
        │
Phase C · 审批中心
   收件箱内直接批准 / 回答 / 拒绝，就地放行 agent
        │
Phase D · 任务指挥台
   美化的任务看板（入口）+ 审批中心（出口）合一，
   主线/支线标记沉淀在看板上，形成完整的多任务指挥闭环
```
